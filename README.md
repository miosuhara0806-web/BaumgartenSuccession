# バウムガルテン王国の継承戦 — アルバ基盤試作

## GitHub Pages での試遊

公開先は `https://miosuhara0806-web.github.io/BaumgartenSuccession/` です。
リポジトリは `https://github.com/miosuhara0806-web/BaumgartenSuccession`。
公開完了は GitHub の Actions と Settings → Pages で確認できます。

`.github/workflows/pages.yml` が `main` への更新時に、既存テスト・構文検査・静的ビルドを実行し、`dist/` だけを公開します。
リポジトリの Settings → Pages → Source は **GitHub Actions** を使用します。
HTML・CSS・JavaScript の参照は相対パスのため、`/BaumgartenSuccession/` 配下でも読み込めます。

公開URLの保存は、その端末・ブラウザ内の IndexedDB を利用します。
ローカル試作URLの保存とは別で、PCとAndroidの間でセーブは同期しません。
Androidでは同じブラウザの通常タブで試遊し、保存後にタブを開き直して「つづきから」と手動ロードを確認してください。

ルートの「Codex実装開始仕様書 v0.3」第13項を対象にした、静的ブラウザゲームです。
初回の停止位置は、アルバの三試練完了、地図帰還、記録閲覧、セーブ／ロードまでです。

## 起動

Node.js 22 以上で、プロジェクトのフォルダーから実行します。追加パッケージのインストールは不要です。

```powershell
node scripts/serve.js
```

ブラウザで <http://127.0.0.1:4173/> を開いてください。HTML の直接ダブルクリックではなく、HTTP 経由で開きます。
停止は起動したターミナルで `Ctrl+C`。ポートを変える場合は、起動前に `$env:PORT = '4174'` を設定できます。
保存はブラウザのサイト単位です。同じブラウザ・同じURLで再開してください。ポートやブラウザを変えた場合の保存は別になります。

```powershell
node --test
node scripts/check.js
node scripts/build.js
```

`check` は JavaScript の構文検査、`build` は `dist/` へ HTML と ES modules をコピーする静的配信用の出力です。
npm がある環境では `npm start` / `npm test` / `npm run check` / `npm run build` でも同じ処理を実行できます。

## 実装範囲

- タイトル、導入、2指揮官、8人のプロフィール、役割制約付き選抜、両陣営確認、出発。
- 5地域の地図。アルバの小①・危機作戦3択の小②・大試練、結果、帰還、完了記録。
- 同行者の任意会話、指揮官の気づき、出典付き情報メモ、条件付き追加案、テオの調査。
- 試練ごとの確定点・政策・隠しタグの保存。合計点、相手側4人、テオ残数は履歴から導出。
- 既読スキップ、差分・版別既読、現在周回の直近200発言ログ。
- 手動3枠とオート1枠、上書き／削除／ロード／新規周回の確認、ロード検証。
- 保存失敗の再試行、複数タブの古い保存拒否、通常保存から独立した王国史の保存形式。
- 地域・会話・イベントをデータで追加できる進行基盤。編成別の全文シナリオは複製していません。

アルバ以外は準備中です。アルバ終了で通常地域完了数は1、得点は0〜20、テオは残り1または2回になります。
遭遇、王都最終章、継承判定、正式王国史の登録は通常の試作では発生しません。
これらの基盤確認用の仮地域・仮イベントは `tests/` 内だけにあります。

## 内容と処理の境界

| ファイル | 役割 |
| --- | --- |
| `src/content/fixture.js` | 人物・地域・場面・本文・会話・情報・選択肢の固定データ |
| `src/engine.js` | 不変コピーによる進行、条件、得点履歴、編成、テオ、ロード検証 |
| `src/storage.js` | IndexedDB、トランザクション、revision、保存枠、既読、王国史 |
| `src/app.js` | 画面、確認、入力抑止、保存後表示、失敗時の再試行 |
| `src/styles.css` | PC／スマートフォン対応の画面配置 |
| `tests/` | 内容検査、全編成、独立機構、保存・UI保存ハンドラーの回帰テスト |
| `docs/implementation-contract.md` | 実装上のデータとモジュールAPIの補完 |

プロフィールと地域の骨子は v0.3 から採用しています。
アルバの台本・同行者会話・メモ・テオの調査事実・具体案・評価文・配点・統治タグ・効果なしの雑談は **fixture** です。
`contentStatus: 'fixture'` と画面表示で識別しています。正式素材の代わりに名前・役割の肖像枠を表示し、地図の画面配置も仮です。
仮配点は小試練0／3／5、大試練0／6／10、条件付き追加案6。追加案は章全体で一件だけで、ハロルドの大試練会話＋情報、またはテオの調査情報で現れます。
この条件・内容・得点は正式な政策評価として確定していません。

## 保存

一つの IndexedDB に `slots`、`readerProfile`、`chronicles`、`meta` を別のストアとして置きます。

- スロットには現在周回だけを保存。会話完了と取得情報はロード地点へ戻ります。
- 周回共通の既読は文章ID＋revision＋名前等の差分キーで記録。ロードや新規周回で巻き戻しません。
- 通常セーブを削除しても王国史と既読は消しません。王国史は確定本文を持つ独立記録です。
- 試練確定は得点・タグ・結果先頭の位置を一括保存。テオも使用履歴・情報・報告先頭の位置を一括保存。
- 保存失敗時は画面とメモリ上の候補を保持し、既存保存を消さずに再試行できます。
- 保存が完了した後、一覧の取得だけが失敗した場合は、再試行で表示だけを更新します。
- revision は `DBの識別子:更新番号`。競合時に最新revisionを黙って取り直して書き込むことはせず、利用者が保存済みの枠を選び直してロードします。
- 非対応版・不正なID・編成・進行・得点・情報履歴などはロード前に拒否。既存データの初期化や再採点はしません。

正式な王国史の登録関数は、全5章完了と `full` モード、実行側と内容側の `reviewed` 指定を必要とします。
試作から正式王国史へ登録する経路はありません。正式な一覧・本文画面は次回以降の施工範囲です。

## 実操作で確認する手順

1. 「はじめから」→導入→指揮官を選びます。人物カードを開き、近接2・遠隔1・回復1を選びます。満員の役割を追加しても他人物が勝手に外れないことを確認します。
2. 両陣営の四人を確認して出発します。地図ではアルバ以外が準備中、継承点が0／100、テオが2回であることを確認します。ここで手動1に保存します。
3. 小①で会話を聞き、吹き出しが消えて情報メモに出典付きで入ることを確認します。判断を確定し、結果の得点を確認します。ブラウザを再読込みし、「つづきから」で同じ結果先頭へ戻っても加点しないことを確認します。
4. 小②で三つの作戦に四人の役割が出ることを確認します。「地図へ一時帰還」→アルバの続きで、同じ判断前へ戻れます。作戦を確定し、結果文にも四人が関与していることを確認します。
5. 大試練の判断前に手動2へ保存します。ハロルド同行なら、その場の会話を完了するまで追加案が表示されないことを確認します。
6. テオ依頼を取り消し、残数が減らないことを確認します。確定すると1回減り、メモと報告が保存されます。報告中に再読込みしても報告先頭から再開でき、残数は1のままです。
7. 大試練を提出し、結果→帰還会話→地図へ進みます。アルバ完了は一地域だけ、王位判定はなく、アルバから点数・政策・取得情報の記録を開けます。完了地点を手動3に保存します。
8. 手動2をロードします。点・位置・テオ・会話・情報・ログが調査前へ戻り、追加案は現在周回の条件成立まで消えます。以前に読んだ会話は再び吹き出しから開け、既読スキップで完了・情報付与できます。
9. 手動1の上書き・削除を取り消し、枠が変わらないことを確認します。手動3をロードするとアルバ完了地点へ戻れます。
10. 新規周回を始める場合、オート置換の確認が出ます。手動枠と既読は残り、新しい周回の会話・取得情報は未取得から始まります。
